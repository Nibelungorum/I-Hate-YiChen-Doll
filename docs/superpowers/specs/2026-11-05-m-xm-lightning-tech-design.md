# M_XM_ 饰品与闪电科技兼容设计

## 已确认的效果

- 只有玩家在 Curios 有效饰品槽中佩戴 `m_xm_` 时生效，背包、手持、放置均不生效。
- 防御端：佩戴者不承受闪电科技电磁炮的正常命中伤害、直接压血和过载处决，覆盖共享命中流程中的光束、蓄力、连锁与范围伤害。
- 攻击端：佩戴者攻击别人时，绕过受害者苍穹织雷的模块护盾、反伤与不死保护，包括已存在的不死保护窗口。
- 不调整费用、连续触发倍率、模块安装状态，不绕过原版护甲或其他模组的保护，不提供对其他伤害来源的无敌。
- 电磁炮免伤不扩展为免疫地形破坏造成的后续环境伤害；电磁麻痹等非伤害效果保持原有逻辑。

## 实施范围

只修改本项目，不修改 `../AE2-Lightning-Tech`。后者作为源码参考；Mixin 的方法签名及调用点必须以用户指定版本的实际 JAR 为准，不能仅依赖旁边项目的源码版本。

添加 Modrinth Maven 仓库和以下依赖：

- 闪电科技：`maven.modrinth:ArHeh5Fz:GGx4RqQt`
- AppliedFlux：`maven.modrinth:oMgZ004U:4x40hq9D`
- AE2：`maven.modrinth:XxWD5pD3:KDnFUmMm`
- Mekanism：`maven.modrinth:Ce6I4WUE:5KzzycBT`
- 闪电科技前置：`maven.modrinth:M5jhzZXH:i3H7uX2O`

采用可选兼容集成：开发环境加载指定依赖；没有安装闪电科技时，不加载针对它的 Mixin，本模组原有玩偶功能仍可使用。保持现有 Curios 可选依赖策略。

## 状态管理

新增服务端全局 Manager，以玩家 UUID 缓存有效佩戴状态。

- 在 M_XM_ 的 Curios `onEquip` / `onUnequip` 回调中立即刷新实际有效槽位，避免多个同款饰品时取下一件误删状态。
- 利用该饰品的 `curioTick` 每 40 tick 核对一次，不增加每 tick 扫描全体玩家饰品的监听。
- 处理登录、重生等生命周期的缓存重建，退出和服务器停止时清理，避免 UUID 缓存跨会话残留。
- 所有战斗查询仅读取缓存，不在伤害处理或 Mixin 内扫描饰品槽。
- 客户端不决定战斗状态，不保存玩家实体强引用。

## 电磁炮免伤

在闪电科技共享伤害处理类的正常伤害调用点，若目标为 Manager 中的佩戴玩家，则跳过该次伤害调用；保留同批次其他目标的处理。

在 `OverloadExecutionService.onHit` 入口，对佩戴玩家直接返回，阻止计血、直接压血和强制处决。不能只拦截 `execute`。

## 穿透苍穹织雷

以伤害来源的实际攻击者判定，包括能通过 DamageSource 归属到佩戴玩家的间接攻击；无玩家归属的环境伤害不触发穿透。

- 在 `CelestweaveArmorDamageHandler.onPre` 入口，对符合条件的攻击跳过该方法，保留进入该方法前已经计算的伤害，不执行模块护盾和反伤。
- 在不死处理类拦截该次攻击的伤害事件、死亡保护、保护窗口和强制死亡恢复路径。
- 使用按受害实体隔离的攻击上下文，把同一次伤害调用内的 `setHealth` / `die` 等无 DamageSource 的入口关联到当前攻击；调用结束必须清理上下文，支持嵌套伤害且不污染其他目标。
- 若致死路径触发后续恢复检查，仍需识别该次死亡来源，防止下一次 tick 被不死模块复活；不能仅靠取消单个伤害事件监听器。
- 不把近期被佩戴者打过等同于所有后续伤害都穿透；非致死攻击结束后，独立环境伤害仍正常获得苍穹织雷保护。

## 验证要求

1. 核对指定 JAR 的真实类名、签名、Mixin 调用点与模组依赖。
2. 自动化测试覆盖缓存更新、重复饰品、40 tick 校验间隔、清理，以及穿透上下文的嵌套隔离和异常清理。
3. 执行 Gradle check / build，检查产物内 Mixin 配置与模组元数据。
4. 能运行时做服务端加载验证，确认 Mixin 正确应用；无法运行的游戏行为验证必须明确标注为未验证。
5. 游戏内验收：佩戴/取下前后电磁炮正常伤害和处决；主目标/连锁/范围/光束；佩戴者近战及归属明确的远程攻击穿透；已有不死窗口、多目标、嵌套伤害、退出重登与重生；无关玩家和环境伤害不受影响。
